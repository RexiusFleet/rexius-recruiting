# Change history

One entry per change made outside the phase table in `CLAUDE.md` section 8, oldest first. Each
says what the change is, the rules it set, and which README section has the detail. This list
lived in `CLAUDE.md` until 2026-11-27; it moved here so that file stays short enough to read at
the start of every session. **Before changing a feature listed here, read its entry**: several
carry rules that are not obvious from the code (what must ship together, what a job never does).

Add a new entry at the end when a change lands, and its one line to the index in `CLAUDE.md`.

- **manual application entry** (PR 8, branch `claude/manual-applications`, 2026-10-26) adds the "Add application" form for paper applications with scans, migrations `20261030000100` to `20261030000300`, and 21 policy checks. Its view migration appends after Phase 7's `furthest_stage_id`, so on the hosted project Phase 7's migrations go first. README "What the manual-entry change created" has the details.

- **Application download** (branch `claude/application-pdf`, 2026-10-28) adds a "Download application (PDF)" button to the drawer, generated in the browser from the tracker's own data (`web/application-pdf.js`, jsPDF pinned on jsDelivr) instead of copying Jotform's PDF, which renders the never-store fields; README "What the application-download change created" records the decision. Later changes, each with its own README section: the **Archived** stage and `archive_before(date)` (2026-10-27), whose rows the tracker hides from the list, pipeline bar and CSV unless "Include archived" is ticked or the Archived chip is picked (2026-10-31, `web/` only); the **pre-2026 cleanup** and the backfill's `--since` cutoff (2026-10-28), extended by the **October cutoff** (2026-10-30: everything archived from before 2026-10-01 deleted with its resumes, records-start note in `web/`); the **CSV formula guard** on export (2026-10-28); **two-factor sign-in** (2026-10-28, section 2); **street addresses dropped** at import (2026-10-28, section 5); the **Security page** (`web/security.js`, 2026-10-29) where a user adds or removes their own authenticator devices and the sign-in screen asks which device a code is from; **six-month retention** of contact details and files (migrations `20261109000100` and `20261109000200`, Edge Function `recruiting-retention`, 2026-10-30, section 5); the **unmatched purge** with `recruiting.purged_submissions`, which the backfill and webhook both honour (2026-10-28); the reference-dropdown corrections in `reference/jotform-forms.json` (2026-10-29); the **CAS free-text position** rule (2026-10-29); and after Phase 9a the **search depth per position** (2026-10-30), the **market check report** as PDF or text (2026-10-30), the **PDF kit** (`web/pdf-kit.js`, 2026-10-30: one shared layout with the Rexius wordmark and embedded Public Sans for the application, market and national PDFs; `npm run pdf:samples` renders checks) and the **national market check** with a cost-of-living adjustment (`recruiting-national-check`, table `national_checks`, 2026-10-30; README "What the national check created"): CAS applications keep the position as typed with `position_id` null, are never "unmatched" and are never purged as such, the 13 purged CAS rows were restored, and the download guard now follows Jotform's signed `files.jotform.com/jufs/` redirect without credentials. The **Spanish 2026 form** (2026-10-31, branch `claude/spanish-form-2026`, migration `20261110000100`) replaces editing the 2025 Spanish form, which would have deleted archived answers; the clone script and its translation table live in `scripts/jotform/`, and the Jotform API key in `.env` needs full access for it.

- **Reopenable positions** (2026-11-01, branch `claude/reopenable-positions`, migration `20261111000100`) make a position the role rather than one opening: `position_openings` and `position_pay_history` (section 6) record each open period and each change of the advertised range, `positions.opened_at`, `closed_at` and `filled_by_application_id` are dropped, and `report_time_to_fill` has one row per opening; the migration and the `web/` change must ship together (README "What the reopenable-positions change created").

- **Bulk status and live dropdowns** (2026-11-09, branch `claude/positions-bulk-status`, no migration): staff tick positions in the list and set them Open or Closed together, and the dropdown-drift warning reads both forms' dropdowns live from Jotform through `recruiting-form-dropdowns` (README "What the bulk status change created"); the function was deployed to the hosted project on 2026-11-09 and answers 401 without a session; PR 41 merged the same day. The rexius.com careers page box sits under the positions list since PR 54 (2026-11-19).

- **Good leads** (2026-11-09, branch `claude/good-leads`, migration `20261113000100`): staff flag an application worth following up later with a reason, an optional revisit date and a keep-until date; the flag holds off the six-month purge for at most twelve months after the application (section 5), the tracker gets a "Good leads" filter, a ★ in the list, a hint when an earlier lead applies again and a leads list on the position drawer, and managers see the flag only; the migration must be applied before the `web/` change publishes (README "What the good-leads change created").

- **Careers page sync** (2026-11-10, branch `claude/careers-sync`, migration `20261114000100`): a daily job (pg_cron → `recruiting.request_careers_sync()` → Edge Function `recruiting-careers-sync`, using the market-check vault secret) reads the Atom feed of https://rexius.com/blogs/careers and closes a position when its last live job page is taken down, opens it when one is published, copies a changed "Pay:" line into the advertised range when it can be read with confidence, and keeps one open rexius.com posting row per live page. Pages are tied to positions by address in `careers_pages` (section 6), never by title alone; status changes only when the site changes, so a hand-set status stays and positions that never had a page are untouched; a page is gone only when it left the feed and answers 404, and a failed, empty or half-empty feed changes nothing. The rules are pure functions in `supabase/functions/_shared/careers.mjs` with tests (`npm run careers:test`); `npm run careers:dry-run` shows what a run would change. It never creates positions and never edits Jotform (README "What the careers sync created").

- **Users page** (2026-11-10, branch `claude/users-page`, migration `20261115000100`): admins invite people with a role, change roles and names, re-send invites, reset a lost authenticator and remove access from a **Users** tab, through the admin-only Edge Function `recruiting-users` (service role; lists and touches only people with a `recruiting.profiles` row, since `auth.users` is shared; removing deletes the profile and keeps a used login); a trigger keeps at least one admin; invite links return only to the tracker's own addresses (README "What the Users page created"); since 2026-11-11 **Add user** can skip the email and give the admin a one-time sign-in link to pass on (`#invite=<token hash>`, redeemed only on a Continue click so link scanners cannot use it up), and pending rows have **Copy sign-in link** (README "Sign-in links without email").

- **Jotform times read as US Eastern** (2026-11-11, branch `claude/jotform-eastern-time`, migration `20261116000100`): Jotform's API writes `created_at` in US Eastern whatever the account's own setting says, so every submission had been stored three hours late; the hosted function secret `JOTFORM_TIMEZONE=America/New_York` fixed new submissions on 2026-11-11, `JOTFORM_CLOCK` is the code default for the webhook and the backfill, and the migration corrected the 156 stored times, their first history rows and the two openings dated from them (README "What the Jotform time fix did").

- **Benefits in the market check** (2026-11-18, branch `claude/market-benefits`, migration `20261117000100`): a run records the benefits each posting lists in twelve fixed categories and the function counts them and compares them with the categories staff tick for the position (`positions.benefits`); a common benefit Rexius has not ticked is shown as a gap, never a score, and a posting that shows no benefits is not counted as offering none; the migration must be applied before the `web/` change publishes (README "What the benefits check created").

- **Update prompt** (2026-11-18, branch `claude/update-prompt`, no migration): the Pages deploy stamps the page and `version.json` with the commit (`scripts/pages/stamp-version.sh`) and `web/update-check.js` shows a Restart bar in an open tab or installed app when a newer deploy is live; it never reloads on its own (README "What the update prompt created").

- **Contact date** (2026-11-19, branch `claude/contact-date`, migration `20261118000100`): the contact form has a **When** field (default now); `contacts.at` is when the contact happened and the new `contacts.logged_at` is when it was written, set only by the trigger `contacts_stamp`, which also refuses a future date; an entry logged more than a day late shows "logged <date>"; the migration must be applied before the `web/` change publishes (README "What the contact date created").

- **Testing sign-in** (2026-11-19, branch `claude/testing-sign-in`, migration `20261119000100`): for the testing window before the tracker moves into the Rexius company app, **Add user** gives the admin a generated temporary password to pass on (no email; it opens nothing until replaced and lapses after seven days), a **Two-factor** column switches the authenticator requirement per person (`current_role()` honours `mfa_required` and is null while `must_change_password`), and the email paths are hidden unless `config.js` has `emailSignIn`; the migration and the function go before the `web/` change (README "What the testing sign-in change created").

- **File viewer** (2026-11-19, branch `claude/file-viewer`, no migration): the tracker's Files column starts with the application PDF (📋, built on click) and it, resumes, portfolios and scans open inside the tracker in `web/file-viewer.js` with a Download button instead of a new tab; only real PDFs and raster images (checked by their first bytes) are displayed, Word `.docx` files are previewed (not converted) by docx-preview inside a sandboxed, opaque-origin frame with its own CSP, and anything else is download-only; server-side conversion to PDF was turned down because it needs an outside service or a converter of our own; the drawer keeps **Download application (PDF)**; files on the Documents page open in the same viewer (README "What the file viewer created").

- **Market link check** (2026-11-26, branch `claude/market-check-link-accuracy-541c4b`, no migration): a market or national check settles each posting's address against the addresses the web search returned (`supabase/functions/_shared/market-links.mjs`, `npm run market:test`) and stores `link` beside `url`: posting, list (a search or careers page with several jobs) or unverified (the model wrote it); the tracker links a name only when it opens that posting and labels the other two; no page is opened, so a posting taken down since still shows as a posting; both functions need deploying (README "What the market link check created").

- **Review fixes** (2026-11-26, branch `claude/project-review-structure-2ba491`, migration `20261120000100`): the Users page sets a temporary password, makes a sign-in link or deletes an unused login only for logins the tracker itself created (`profiles.login_made_by_tracker`), never for one a person had for the other app first; reports read past the Data API's 1,000-row cap in pages; the six-month file purge empties the application's whole folder, not only the paths its rows name; the migration goes before the functions and `web/`; the tracker still shares the origin `rexiusfleet.github.io` with the organization's other Pages sites, and the steps for a domain of its own are written up but not done (README "What the review fixes created").

- **Review hardening** (2026-11-26, branch `claude/review-fixes-2`, migration `20261121000100`): `web/index.html` carries a Content-Security-Policy and integrity hashes on the CDN scripts (`npm run csp:check` after changing a library version or the Word-preview frame script; a new Supabase address must be added to `connect-src`), jsPDF is 4.2.1, staff add only `origin = 'manual'` rows from the browser and cannot change origin, Jotform ids, purge stamps or a Jotform row's `submitted_at`, `archive_before` and the seasonality report use Oregon dates, the funnel and time-to-fill count a hire only while the application is still hired, an unfinished market check no longer counts as a good run, `profiles` is readable by admins and by each user for their own row with names and roles in the view `profile_names`, staff get a notice when the file purge is behind (`retention_backlog()`), a notes save never overwrites someone else's notes, and the careers sync writes its page table last; the migration and `recruiting-careers-sync` go before `web/` (README "What the review hardening created").

- **Review follow-ups** (2026-11-27, branch `claude/review-fixes-3`, migration `20261122000100`): links in the tracker are made only from http and https addresses (`safeHref` in `web/app.js`; `postings.url` has a matching check), sign-out clears the session on the device even when the server cannot be reached and reloads the page, the applied-on date and date filters use the Oregon date whatever zone the device is in, table rows open from the keyboard, a job page renamed on rexius.com (a permanent redirect to another listed job page) keeps its position instead of closing it, the webhook's Jotform calls time out and retry a 404, two edge cases in the good-lead trigger are fixed, `.github/workflows/tests.yml` runs the unit tests, `npm run csp:check` and the policy checks on every pull request, the Pages workflow pins its actions by commit, and this history moved here from `CLAUDE.md` (README "What the review follow-ups created").
